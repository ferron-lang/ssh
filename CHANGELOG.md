# Changelog

Versions stay `v0.x` until the API settles: the minor version marks changes
that may break callers, the patch version marks fixes.

## v0.2.0

Moves to Ferron 0.10.0-alpha.3. Breaking for callers: secrets are
`std.crypto` secrets, and `SshError` gained a field and lost `Eq`.

- Requires `ferron >=0.10.0-alpha.3`; CI pins `FERRON_REF:
  v0.10.0-alpha.3`.
- Passwords and passphrases are `std.crypto.Secret` on both sides.
  `ssh.client.Secret` and `Secret.new(text)` are gone: write
  `Secret.from_bytes(text.utf8_bytes())`. A secret is affine, so `Auth`
  and `ClientConfig` move instead of being copied (`auth: move auth`).
  Secrets are zeroed when released.
- `PasswordCheck` is `dyn Callable[(String, Secret), Bool] + send`: the
  server's check gets the password as a secret and reads it with
  `expose_bytes()`.
- `SshError` has `cause: Option[ActorError]`, its `#[source]`: an `Actor`
  error keeps the `ActorError` behind it, which `source()` and
  `AnyError.downcast` find. `SshError` no longer derives `Eq`, since
  `ActorError` has none; compare errors by `kind`. A struct literal of
  `SshError` needs `cause: None`.
- `SshErrorKind` derives `Variants` (`variants()`, `name()`,
  `from_name()`, `Parse`).
- Each server connection's session moves into its actor at spawn and
  closes when the actor ends.
- The binding generates both key file functions with a NULL passphrase
  (`[nullable]` in `ffi.toml`) and sizes the callback tables with
  `size_of`; `src/sys/hand.fer` keeps only libc's `umask`.
- The README lists the algorithms the server offers and the package's
  limits, and documents every public item.

## v0.1.0

First release: SSH for Ferron programs, both sides, through FFI over the
system `libssh` (0.12 or newer).

- `ssh.server`: `serve(actors, clock, fs, config, handler)` listens and
  calls the handler for each authenticated connection with a shell, each
  connection an actor pinned to a thread of its own. `Config` sets the
  address and port, the Ed25519 host key file (created with mode 0600 on
  the first run), `max_connections`, `login_timeout`, `allow_guests`, and
  `password`. It refuses `exec`, subsystems, forwarding, and a second
  channel.
- `ssh.session`: `Session`, lent to the handler: `user`, `identity`,
  `term`, `size`, `variable`, `poll` (the `Input`s `Data`, `Resize`,
  `Closed`), and `write`. `Identity` is `Key(algorithm, fingerprint)` for
  a client that proved its public key, `Password(user)` for one that
  `Config.password`, a `PasswordCheck` (`dyn Callable[(String, String),
  Bool] + send`), accepted (three attempts per connection), or `Guest`
  for one that came in through `keyboard-interactive` without a key.
- `ssh.client`: `connect(net, fs, clock, config)` returns a `Client`, a
  resource that disconnects when it closes. `ClientConfig` has the host,
  port, user, timeout, a `HostKeyPolicy`, and the `Auth` methods to try in
  order.
  - Host key verification is mandatory: `Strict(known_hosts)`,
    `AcceptNew(known_hosts)`, or `Fingerprint("SHA256:...")`; a server
    whose key is not the recorded or pinned one always fails with
    `HostKeyChanged`. There is no policy that accepts any key.
  - Authentication: `KeyFile(path, passphrase)`, `Agent`, and
    `Password(secret)`; a failed login says what was tried and what the
    server accepts. `Secret` keeps passwords and passphrases out of text.
  - `Client.run(command, timeout, max_output)` returns a `CommandOutput`
    (`stdout`, `stderr`, and an `ExitStatus`: `Code`, `Signal`, or
    `Unknown`), failing with `Timeout` or `TooLarge` past its limits.
  - `Client.shell(pty, body)` lends `body` a `Shell` on a terminal:
    `write`, `poll` (the `Event`s `Stdout`, `Stderr`, `Ended`), and
    `resize`.
  - The client reads no `~/.ssh/config`, default identity, or system
    `known_hosts`.
- `ssh.error`: `SshError` with an `SshErrorKind` (`HostKey`, `Listen`,
  `Closed`, `Config`, `Connect`, `Timeout`, `HostKeyUnknown`,
  `HostKeyChanged`, `KnownHosts`, `Authentication`, `Channel`, `TooLarge`,
  `Actor`) and libssh's message.
- Bindings: `src/sys/` generated by `anvil ffi gen` from the libssh
  headers, pinned to the functions the package calls so the output is the
  same for the 0.12.0 and 0.12.2 headers; the two key file functions that
  take a NULL passphrase, and libc's `umask`, are hand-written in
  `src/sys/hand.fer`. libssh 0.11 and older lack `ssh_pki_generate_key`
  and the keyboard-interactive server callback and do not work.
- `scripts/interop` checks the client against a private OpenSSH `sshd`
  and against the package's own server, through `examples/probe`.
- Requires `ferron >=0.10.0-alpha.2`; CI pins `FERRON_REF:
  v0.10.0-alpha.2`, builds libssh 0.12.2 from its sources (Ubuntu's
  runners ship 0.10 and 0.11), and checks `live_handles=0` after
  `anvil test`.
